# 第一天作业：LED 扩展、流水灯与状态机

> 题目 1~5 只使用板载 LED；题目 6 会用到蜂鸣器。
> 开始前先阅读 `README.md` 中的结构体、枚举、宏函数与 `inline`、数组与 `const` 表、状态机部分。

## 一、作业说明

种子工程中 `main.c` 只保留一个 LED 的亮灭循环，并使用无参数 `led_on()` / `led_off()`。本作业必做四道，选做两道（题目 5~6，按难度递增）：

1. 扩展 LED 函数；
2. 实现流水灯；
3. 封装流水灯；
4. 遥控流水灯状态机。

`reference/` 中保存了题目 3 的封装参考，不加入 Keil 工程。

## 二、已经提供的部分

- `hardware/inc/led.h` 和 `hardware/src/led.c`：无参数 `led_on()` / `led_off()` 已经实现，只操作 LED1；
- `main.c`：单个 LED 亮灭循环 + 上电蜂鸣；
- `main.c` 的 `USER CODE 2`：已经预留题目 3 的初始化调用位置；
- `reference/`：题目 3 的封装参考，不加入 Keil 工程；
- 编译、下载、烧录流程已经可用。

下载种子工程后，板子应该先响一声上电蜂鸣，然后“一颗 LED 反复亮灭”。

### 题目 1：扩展 LED 函数

把 `hardware/inc/led.h` 和 `hardware/src/led.c` 中的无参数 `led_on()` / `led_off()` 扩展为：

```c
void led_on(uint8_t led_num);
void led_off(uint8_t led_num);
```

要求：

1. 支持 LED1 ~ LED4；
2. 用宏函数或 `inline` 函数做编号越界检查；
3. 非法编号直接返回，不操作引脚；
4. `main.c` 的单灯循环同步改为 `led_on(0U)` / `led_off(0U)`。

### 题目 2：实现流水灯

实现一个流水灯函数，让四颗 LED 依次亮灭。

要求：

1. 函数名和存放位置不限；
2. 实现后能在 `main` 循环中调用；
3. 下载后能看到四颗 LED 依次亮灭的现象。

### 题目 3：封装流水灯

文件组织不限：可以新建文件（例如按 `reference/` 的结构拆出 `led_flow.h` / `led_flow.c`），也可以都在原文件里完成。

要求：

1. 用结构体定义一次亮灭的参数，例如 LED 编号、亮多久、灭多久；
2. 实现 `blink()` 函数，默认控制单颗 LED，内部封装 `led_on()` / `led_off()` 和延时；
3. `main.c` 中不允许调用 `led_on()` / `led_off()`（要求是"main 调不到它们"，不是"删除头文件声明"；实现手段见 `reference/`）；
4. 将题目 2 的流水灯函数升级为调用 `blink()`，并只暴露一个公共流水灯函数；
5. `main.c` 只能调用封装好的公共流水灯函数，不能直接调用 `led_on()` / `led_off()` 或自己写流水灯逻辑；
6. 下载后能看到四颗 LED 依次亮灭的现象。

提示：封装思路、常见卡点、多灯驱动与 `led_toggle_mask()` 示例都在 `reference/`，先把思路理解清楚再动手。

### 题目 4：遥控流水灯状态机

假设有一个遥控器，上面有三个按钮；遥控器到板子的通信链路已经打通，板子侧有接口：

```c
int get_signal(void);
```

`get_signal()` 会返回 `0`、`1`、`2` 三个数字，分别代表三个按钮。

请用枚举设计状态机，实现遥控流水灯：

1. 用 `enum` 定义三种流水灯模式：逐个亮灭、两两亮灭、一起亮灭；
2. 状态机根据 `get_signal()` 的返回值切换对应模式；
3. 由于没有真实遥控器，可以用全局变量 `int signal;` 代替 `get_signal()`，手动给 `signal` 赋 `0`、`1`、`2` 来观察模式切换；
4. 现象：给 `signal` 赋不同值，板子切换不同流水灯模式。

### 题目 5：非阻塞调度（选做）

> 题目 4 的阻塞版状态机里，切换模式要等当前这一步播完（最多一个步骤的延时）。本题把它改造成非阻塞：每轮循环只查一次时间，信号一变立刻切换，并加入空闲（IDLE）模式。

要求：

1. 在题目 4 的三种流水灯模式基础上，`enum` 新增 `IDLE` 状态；`signal` 取值扩展为 `0`~`3`：`0` 表示无按键（回到 `IDLE`，四颗 LED 全灭并停在原地），`1`/`2`/`3` 对应题目 4 的三种模式（语义与原来一致，编号顺延一档）；
2. 基于 `HAL_GetTick()` 封装计时器：用 `struct` 记录起始时刻，提供"启动 / 查询是否到期"之类的函数；所有定时必须走它，不允许在循环里散写 `HAL_GetTick()` 比较；
3. 计时器是**单次触发**：到期后不重新启动就不会再次触发，请把这一语义写进注释；
4. 把状态机改写为非阻塞：`main` 的 `while(1)` 每轮调用一次更新函数，由计时器决定何时切到下一步；**效果播放路径上不得出现 `HAL_Delay()`**（上电初始化的一次性延时除外）；
5. **立刻切换**：`signal` 变化后，下一轮更新立刻进入新状态，不需要等当前步骤播完；
6. 现象验证：依次把 `signal` 赋 `1`/`2`/`3`/`0`，板子立刻切换对应模式，`0` 时四颗 LED 全灭。

提示：非阻塞下"立刻切换"是免费的——每轮循环都读一次 `signal`，下一轮自然就到新状态。

### 题目 6：模式绑定蜂鸣器（选做）

> 题目 5 的调度器已经能"立刻切换模式"。本题把蜂鸣器节奏绑进模式。四种模式（含 IDLE）编号：**模式 1 = IDLE、模式 2 = 逐个亮灭、模式 3 = 两两亮灭、模式 4 = 一起亮灭**（对应题目 5 的 `signal` `0`/`1`/`2`/`3`）。蜂鸣器只在后两种流水灯模式（模式 3、模式 4）下运行：模式 3 间隔较长地鸣叫，模式 4 急促短鸣。蜂鸣器的工作不应该影响流水灯切换节奏，且切换模式时蜂鸣器节奏**立刻跟随**。

要求：

1. 用 `struct` 描述一次鸣叫的配置（响时长、停时长），作为模式配置的一部分：模式 3（两两亮灭）使用"间隔较长"的单响（例如响 200ms、停 800ms），模式 4（一起亮灭）使用"急促短鸣"（例如响 50ms、停 100ms）；
2. 蜂鸣器只在模式 3、模式 4 运行：模式 1（IDLE）、模式 2 下必须静默；模式切换时蜂鸣器节奏**立刻跟随**，不存在"上一次鸣叫没播完"的残留；
3. 必须复用题目 5 的计时器，效果播放路径上不得出现 `HAL_Delay()`，也不得另写一套延时逻辑；
4. **不要求回到 `IDLE`**：本题没有"报警播完自动回待机"之类的生命周期要求——`signal` 切到模式 1/2 时蜂鸣器直接停止即可；
5. 蜂鸣器的引脚调用只允许出现在蜂鸣器封装内部（沿用 `buzzer.h` / `buzzer.c` 的接口），节奏推进逻辑建议独立成函数，不要在 `while(1)` 里散写引脚操作；
